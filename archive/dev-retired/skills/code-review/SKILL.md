# Code Review Skill

This skill exposes capabilities for coordinating multiple specialized review agents to analyze code from security, memory safety, code quality, and language-specific idiomatic perspectives.

## Available Functions / Sub-routines

### 1. `parallel_review`
- **Description**: Spawns and runs multiple reviewer sub-agents (Security, Memory Safety, Style/Quality, and Effective Series) in parallel over a given code block or diff.
- **Parameters**:
  - `code_content` (string): The code content or git diff to be reviewed.
  - `language` (string, optional): The programming language. If omitted, it will be auto-detected.
  - `sub_agents` (array of strings, optional): List of agent names to run. Defaults to `["code-reviewer", "reviewer-security", "reviewer-memory-safety", "reviewer-style-quality", "reviewer-effective"]`.

### 2. `integrate_findings`
- **Description**: Merges findings from parallel reviews, resolves duplicate issues, categorizes findings, and sorts them by severity.
- **Parameters**:
  - `reports` (array of objects): The Markdown reports generated by the sub-agents.
- **Returns**: A unified Markdown report matching the schema below.

---

## Integration Report Schema

The consolidated report returned by the orchestrator must follow this structure:

```markdown
# Consolidated Code Review Report

## Executive Summary
- **Overall Assessment**: [e.g., Critical issues found / Minor style improvements suggested / Clean]
- **Summary Metrics**:
  - **Critical Issues**: [Count]
  - **Warnings**: [Count]
  - **Info/Suggestions**: [Count]

---

## Detailed Findings

*(Grouped by File name, then ordered by Severity: CRITICAL -> WARNING -> INFO)*

### File: `[Filename]`

#### 1. `[Issue Title]` (`[Severity]`)
- **Category**: [Security | Memory Safety | Style & Quality | Effective Idioms]
- **Reviewer**: `[Agent Name]`
- **Description**: [Detailed description]
- **Offending Code**:
  ```[language]
  [offending code snippet]
  ```
- **Recommended Fix**:
  ```[language]
  [corrected code snippet]
  ```
- **Rationale**: [Reasoning / Standards citation]

---

## Conclusion
A final sign-off statement summarizing next steps and action items for the developer.
```
