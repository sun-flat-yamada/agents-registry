# Update Harness Skill

This skill implements the execution and deployment phase of the Harness Engineering lifecycle. It takes an approved **Harness Improvement Plan (HIP)** (generated by `retrospective-harness`) and safely applies the updates across the repository's harness layers.

## Safety Directives

To prevent repository corruption or regression in agent capabilities:
1. **Atomic Backup First**: Before modifying any existing harness file, create an in-memory or temporary backup under `.harness-backup/`.
2. **Deterministic Validation**: Every file change is immediately validated using JSON/YAML parsers, linters, and dry-run execution.
3. **Auto-Rollback on Error**: If any validation check fails, all touched files are instantly restored to their pre-update state, and a descriptive error report is generated.
4. **Idempotency**: Applying the same improvement item multiple times produces the exact same valid state without duplicate rules or corrupted configurations.

---

## Execution Workflow

### Step 1: Ingest & Parse the Improvement Plan
- Locate and read the target improvement plan:
  - Default path: `plans/harness-improvement-plan.md` (or a path supplied by the user).
- Parse the prioritized action items (`[P0]`, `[P1]`, `[P2]`), target file paths, and replacement diffs.

### Step 2: Pre-Execution Backup
- Create a timestamped backup directory:
  ```powershell
  $backupDir = ".harness-backup/$(Get-Date -Format 'yyyyMMdd-HHmmss')"
  New-Item -ItemType Directory -Path $backupDir -Force
  ```
- Copy all target files into `$backupDir`.

### Step 3: Apply Changes by Harness Layer

#### Layer A: Master Agent & Skill Layer (`skills/`, `agents/`, `commands/`)
- Update or create `SKILL.md` or `agent.md` files according to Agent Skills Standard.
- Validate YAML frontmatter (`name`, `description`).

#### Layer B: Lifecycle Hooks & Security (`hooks/`, `hooks/hooks.json`)
- Update hook matchers and scripts (`PreToolUse`, `PostToolUse`).
- Validate JSON schema compliance.

#### Layer C: Instructions & Rule Files (`instructions/`, `CLAUDE.md`, `.cursorrules`)
- Apply surgical edits to instructions without ballooning file sizes.
- Ensure cross-platform path rules are respected.

#### Layer D: Packaging & Multi-Harness Sync (`.claude-plugin/`, `apm.yml`)
- Register new skills or agents in `.claude-plugin/plugin.json` and `apm.yml`.
- Execute `./scripts/sync-apm.ps1` to propagate updates to the `.apm/` compatibility layer.

### Step 4: Verification Suite
Run the automated verification suite:
1. **Syntax Check**: All modified JSON and YAML files parse without syntax errors.
2. **Hook Dry-Run**: Execute `./hooks/pre-commit.ps1` or relevant validation hooks.
3. **APM Consistency**: Execute `powershell -File ./scripts/sync-apm.ps1 -VerifyOnly`.

### Step 5: Post-Update Audit Report
Produce an execution summary:
- Status: `SUCCESS` / `ROLLED_BACK`
- Files Modified: [List of paths]
- Tests Executed: [Validation results]
- Next Steps: Recommendations for live testing in subsequent agent sessions.
